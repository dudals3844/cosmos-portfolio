01 / DEPLOYMENT · KUBERNETES

Kubernetes로 잇는 클라우드의 운영, 로컬의 연구.

클라우드와 로컬의 노드 4개를 Kubernetes 클러스터 하나로 묶었습니다. 계속 켜두어야 하는 운영은 클라우드에, 계산이 많은 연구는 로컬 노드에 배치하고, 연구 데이터는 NAS로 공유합니다.

↔ 움직이는 점은 요청·응답을 나타냅니다. 작은 화면에서는 구조도를 좌우로 움직여 보세요.
  • Kubernetes: 노드 4개 클러스터
  • 클라우드: 운영·주문
  • 로컬 2개: 연구·분석
  • NAS: 연구 파일 공유
모든 저장소를 NAS에 두나요? ＋

아닙니다. 공유 연구 파일은 NAS의 NFS 마운트를 활용하지만, PostgreSQL·Redis·Agent의 상태 저장처럼 지연과 파일 잠금에 민감한 데이터는 각 서비스의 로컬 디스크·전용 볼륨을 사용합니다. 공유 파일과 실행 상태를 구분합니다.

02 / SERVICES

역할을 나누고, 계약으로 연결합니다.

서비스를 누르면 입력·처리·출력과 사용 기술을 펼쳐볼 수 있습니다.

Listener수집→Preprocessor정제→연구·전략cosmos-agent · cosmos · thinker→Trader주문→Manager집계·확인

위 연결은 역할을 요약한 논리 구조입니다. 서비스 사이의 요청·결과·계좌 이벤트는 양방향으로 오가며, 연구 평가와 주문 실행의 권한은 분리합니다.

listener데이터 수집＋

Client의 요청을 Broker가 벤더별로 처리합니다.

  • 벤더별 호출 제한
  • 미완료 작업 인수·재처리
  • 여러 Client가 공통 수집 경로 이용

캐시는 Broker 상태·거래소 정보를 재사용합니다. 모든 시세 요청을 캐시로 대체하는 구조는 아닙니다.

preprocessor데이터 정제＋

수집한 데이터를 연구에 쓸 수 있는 형태로 바꿉니다.

  • 원시·정제 단계 분리
  • 시점 정합성 PIT
  • Parquet 재사용

전략이 같은 기준의 데이터를 사용하도록 정제합니다.

cosmos-agent연구·측정＋

탐색, Workflow, 측정과 평가의 책임을 나눕니다.

  • 검색·출처 확인
  • 작업 범위와 복귀 경로
  • 측정과 평가 분리

측정 결과는 권고의 근거이며 실자금 투입 승인이 아닙니다.

cosmos공통 연구 기반＋

전략마다 다시 만들던 코드를 공통 라이브러리로 묶습니다.

  • 공통 데이터 인터페이스
